# 海岸浪花演示

打开 `res://coast_lab/coast_demo.tscn`，按 F6。独立场景，不改变主场景。

## 水体一共分成几个部分？

**只算水体效果，可以拆成 5 个部分；加上下面的沙滩，共 6 个部分。**
这是一种按视觉作用划分的方式，5 个水体部分由同一个 Shader 合成。

| 部分 | 画面中的作用 | 当前实现与代码对应 |
| --- | --- | --- |
| ① 常驻海水 | 构成大面积海面，提供稳定的基础水位 | 根据距岸距离计算 `base_depth`；水深参与透明度计算 |
| ② 浪带来的薄水层 | 浪来时覆盖浅滩，经过后逐渐变薄、露出沙底 | `wave_event()` 根据局部经过时间 `age` 计算 `film`；多道浪的薄水取最大值，保存在 `waves.x` |
| ③ 浪头白色泡沫 | 表现向岸推进的浪尖 | `crest_time` 控制前缘出现时间，`leading_fill` 保持连贯，`foam_hole_field()` 提供不规则泡孔 |
| ④ 浪后残留泡沫 | 表现浪经过后留下的泡沫块 | `residue` 使用固定世界坐标的泡孔；随 `age` 增大孔洞，再原地消散，保存在 `waves.w` |
| ⑤ 水面波光 | 表现水面闪动的反光 | `simplex_height_gradient()` 生成微小起伏与梯度，构造 `surface_normal`，计算模拟镜面高光 `glint` |

**⑥ 沙滩底层**包含沙粒、沙砾和固定的深色湿沙区域。
水的透明度降低后，可以看到这层真实绘制的沙底。当前湿沙是固定范围的深色遮罩，不记录浪经过后的历史湿度。

### 在 Godot 中实际怎么画？

核心海岸画面由两个 `ColorRect` 承载，另外还有参数面板、背景等界面节点：

- **沙滩层**：脚本变量 `ground`，材质的 `render_ground = true`，输出沙滩颜色。
- **水体层**：脚本变量 `surface`，材质的 `render_ground = false`，合成上表中的 5 个水体部分。

两层共用 `coast.gdshader` 的代码，使用各自的材质实例。
运行时，`coast_demo.gd` 在预览 `SubViewport` 中创建这两个层；编辑器中对应 `GroundPreview` 和 `EditorPreview` 两个预览节点。

### 合成顺序

1. 先绘制沙滩底层。
2. 在水体 Shader 内，把基础水深与各道浪中最厚的薄水相加：`water_depth = base_depth + waves.x`。
3. 用水深计算 `water_alpha`：薄水更透明，深水更不透明。
4. 将波光叠在水色上，得到带反光的水面。
5. 将浪头泡沫与残留泡沫合成后，再叠到水面上。
6. 输出最终颜色和 Alpha，让透明区域露出底下的沙滩。

波光与泡沫分别有自己的 Alpha。因此，浅水比较透明时，仍然可以看到亮片和白色泡沫。

### 海岸距离是共同依据

`shore_distance(p)` 计算当前位置的海岸距离 `d`：

- `d = 0`：参考海岸线。
- `d > 0`：水侧。
- `d < 0`：陆侧。

它控制基础水深、浪到达的时间、上岸范围以及泡沫出现的区域。
它是上述效果的共同输入；默认曲线算法得到的是岸边近似距离。
可视化时，在演示下拉菜单选择「海岸距离」「泡沫遮罩」「动态水深」「原地消散的碎泡沫」或「水面高光」，逐部分观察。

- coast_material.tres：水体材质。

## 操作

调整浪花推进速度、波光亮度/密度/大小/变化速度、浅水/深水不透明度、每组浪花数量、每组时长、泡沫宽度、纹理大小、浪头连贯度、开孔程度、上岸距离、水边随机幅度、过渡带半宽、像素大小。
0 完全透明，1 完全不透明；泡沫使用独立 Alpha。
空格暂停，R 重新播放。时间轴在当前组内定位。默认每组 5.5 秒发出 3 道浪。右侧面板可滚动。

## 算法与边界

1. 世界坐标按 pixel_size 量化，弯曲海岸公式提供岸边近似有符号距离。
2. 所有仍有贡献的浪分别以固定种子计算到达时间；波峰只向岸传播，经过位置依次铺开薄水。
3. 每个位置的薄水寿命不同，陆侧先消退，海侧停留更久；跨周期残留由历史事件自然延续。
4. 水面采用两层单纯形噪声及其解析导数，模拟微小水面法线，再计算 Blinn–Phong 高光。沙底与浪边仍用柏林噪声；泡沫孔洞使用随机中心和随机半径的 Cellular 风格距离场。
5. 常驻海水深度固定，其上叠加局部薄水厚度，再计算透明度。泡沫使用独立 Alpha。
6. 底层绘制沙底，上层绘制透明水体。湿沙为固定范围遮罩，不记录历史湿度；沙底噪声仍逐帧计算。

当前版本无湿沙双 RT 或沙底烘焙缓存。演示用 SubViewport 显示最终画面。
海岸形状为公式定义，内置距离只在岸边近似合理，不是远场精确 SDF。

## 传播浪头 + 局部薄水（无历史反馈模拟）

- 核心函数 wave_event：age = 当前周期时间 - 发射时刻 - 沿岸延迟 - arrival / wave_speed。
- 每道浪种子固定，显式计算仍有贡献的历史事件，避免换组时残留泡沫跳变。
- 浪头只向岸传播；前缘经过时迅速增厚，后方薄水依据各位置寿命消退。
- 陆侧薄水寿命短，海侧长，形成退水；不再往返移动统一水边，也不再平移整片水纹。
- 泡沫孔洞固定于世界位置，随 age 提高侵蚀阈值并消散；没有跟着退水线返回的 rim。
- drain_speed：局部薄水消退速度。foam_residue：浪后碎泡沫强度。
- 新增“原地消散的碎泡沫”视图。可暂停后拖动时间轴观察。
- 仍是纯 Shader 的可复现视觉近似，没有 RT 历史、湿沙记忆或真实流体守恒。

## 多道浪覆盖浅水边缘

- wave_count：每组 1～4 道浪，默认 3；wave_period 表示一组的时长。
- 发射间隔 = wave_period / wave_count。只增加发射频率，单道浪的传播速度、寿命不变。
- 独立事件编号决定随机形状；发射时间 = 编号 / wave_count（以组周期为单位）。
- 薄水厚度取 max；泡沫覆盖率用 1-(1-a)(1-b) 合并，不直接累加亮度。
- 默认 1 倍速、3 道时计算 5 个仍可能有效的事件；0.5 倍速、4 道时最多计算 9 个。增加浪数或放慢速度，会增加事件计算。
- 浪头仍只向岸传播，浪后泡沫原地侵蚀消散，无 RT 历史。

## 浪花速度与波光

- `wave_speed`：0.5～2.5 倍，只缩短/延长每道浪的传播时间。发射间隔不变，薄水消退由 `drain_speed` 控制；每组时长仍是整体时间基准。
- `age = 当前组时间 - 发射时刻 - 沿岸延迟 - arrival / wave_speed`。
- 前缘与铺水上升段使用 `age * wave_speed`，避免快浪变得特别宽；残留泡沫与排水继续按 age 消退。
- 按 `0.10 + 0.56 / wave_speed + 0.80` 保存足够久的历史事件，慢速下不会提前删掉仍有贡献的浪。拖动速度参数会重新定位现存浪头，固定参数播放连续。
- 水面用两层不同方向移动的二维 Simplex 噪声计算高度及解析梯度；从梯度构造模拟法线。使用固定斜上方光线和俯视视线的半角向量，计算 Blinn–Phong 高光。
- `sparkle_scale`：亮片大小；`sparkle_speed`：水面起伏变化速度，0 为静止；`sparkle_density`：高光密度，0 关闭亮点；`sparkle_strength`：亮度。
- 世界坐标仍按 `pixel_size` 量化。高光具有独立的反射覆盖率，受水深和水体范围限制，泡沫最后叠在高光上。
- 这是 2D 画面中模拟的高光，不依赖 Godot 灯光节点，也不新增 RT 或法线贴图。

原理参考：
- Simplex 梯度噪声：[Stefan Gustavson 的噪声实现与说明](https://github.com/stegu/webgl-noise)。本例沿用现有 hash 生成梯度方向，直接计算三角形三角点贡献和导数。
- 水面起伏、法线与反射：[GPU Gems：Effective Water Simulation from Physical Models](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)。

## 泡沫造型

- 移除原先 p/4 高频噪声对整片泡沫的切割，前缘保留较连贯的浅白浪尖。
- `foam_hole_field`：世界坐标划分格子，每格设置随机圆心和半径，遍历 3×3 邻格取最小归一化距离平方。加入静止坐标扰动，形成大小不一、边缘圆钝的不规则泡孔。
- 孔洞锚定世界坐标及每道浪的种子。随局部 age 增大孔洞半径，让网状泡沫逐渐断裂，原地消散。
- `foam_pattern_size`：泡沫纹理尺度，默认18世界像素；`foam_front_solid`：浪头连贯度；`breakup`：开孔程度，越大越稀疏。
- 前缘与后方泡沫分开控制，继续使用独立 Alpha。水面 Simplex 高光和浪花速度功能保留。
- 仅在泡沫仍可见的位置计算九邻格距离，不增加 RT。
